# ADR-0012：显式只读服务组合根与独立运维探针

- 状态：Accepted
- 日期：2026-07-27

## 背景

M1-H 已形成完整的只读认证、授权和查询链，但各组件仍由示例代码分别组装。直接在领域包中读取环境变量、创建 Pool 或监听端口，会把部署生命周期与领域逻辑耦合，并使启动失败、依赖探测和优雅关闭难以验证。

## 决策

1. 新建独立应用 `apps/read-only-governance-service`；
2. 只有应用组合根可以读取环境配置、创建 PostgreSQL Pool 和监听端口；
3. 启动顺序固定为配置、migration、JWKS 预热、组件组装、监听和 readiness；
4. `/live` 与 `/ready` 在业务认证路由之外实现；
5. `/ready` 只公开依赖名称和成功状态，不公开错误细节；
6. 运行事件通过 Port 输出，通用事件禁止敏感字段；
7. 关闭流程先撤销 readiness，再关闭连接和 Pool；
8. 容器必须使用非 Root 用户；
9. 应用仍然只开放已有五条业务 GET 路由。

## 结果

优点：

- 领域包保持环境和部署无关；
- 启动、探针、关闭和容器行为可以独立测试；
- 依赖失败不会形成半启动服务；
- 运维端点不扩大业务数据暴露面；
- 未来 Kubernetes 或其他平台可复用稳定探针。

代价：

- 应用组合根需要维护较多显式依赖；
- Subject Mapping 当前仍通过静态配置提供；
- PostgreSQL Driver 在运行镜像中单独安装；
- 本阶段不提供生产部署清单。
