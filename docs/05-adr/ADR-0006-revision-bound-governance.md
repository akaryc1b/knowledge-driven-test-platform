# ADR-0006：审核决策绑定 Registry Revision

- 状态：Accepted
- 日期：2026-07-27

## 背景

仅依靠 Registry 生命周期无法证明发布前由谁审核、审核针对哪一版正文，以及项目是否允许该主体执行操作。若审核只绑定知识 ID 和版本号，草稿退回修改后，旧批准可能被错误复用。

## 决策

1. 治理编排位于 Registry Port 之上，不修改 Registry 的纯领域状态机；
2. 每个审核决策绑定 `knowledgeKey` 和精确 `reviewRevision`；
3. 草稿退回、替换和重新提交后，旧 revision 的决定自动失效；
4. 原始作者取自 Registry 的第一条审计事件；
5. 默认禁止作者审核和发布自己的知识；
6. 发布是独立动作，必须重新读取当前 revision 的全部批准；
7. 项目授权通过独立 Port 注入，治理核心不依赖具体身份系统；
8. 知识快照通过独立不可变 Store Port 保存。

## 结果

优点：

- 消除“审核过旧正文”的风险；
- 审核证据与 Registry 状态可关联；
- 适配任意身份、数据库和传输层；
- 多项目权限边界明确；
- 发布策略可按风险级别加强。

代价：

- 审核决定需要独立持久化；
- Registry 与审核存储的跨资源原子性需要后续 Unit of Work；
- 重新提交后必须重新审核；
- 发布流程比直接状态转换更严格。
