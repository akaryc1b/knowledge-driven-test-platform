# ADR-0014：堆叠合并前先生成发布证据

- 状态：Accepted
- 日期：2026-07-27

## 背景

M1 由多个独立 PR 组成。单个 PR 的成功不能证明最终头分支具备完整的认证、授权、数据库、HTTP、容器和部署行为，也不能证明堆叠顺序没有断裂。

## 决策

1. 在合并堆叠 PR 前创建 M1-RC1 候选定义；
2. 候选记录 PR 顺序、base/head 和 head SHA；
3. 最终头分支必须运行真实 PostgreSQL + JWKS + JWT + HTTP 端到端测试；
4. 发布证据必须包含候选和 Manifest digest；
5. 本地 Docker image ID 不能视为生产 Registry digest；
6. 候选通过时仍保持 `productionEligible=false`；
7. PR 由人工按顺序合并，每次合并后重新检查下一 PR。

## 结果

优点：

- 防止只看局部 CI 就宣布 M1 完成；
- 为堆叠合并提供确定顺序；
- 将生产阻断项显式化；
- 发布证据不依赖敏感配置。

代价：

- 候选验证增加一组真实数据库端到端测试；
- 合并后还需在 main 再运行一次最终验收；
- 外部镜像和目标集群证据必须由后续发布流程补充。
