# ADR-0009：成员关系驱动的默认拒绝授权

- 状态：Accepted
- 日期：2026-07-27

## 背景

M1-C 和 M1-E 已定义项目授权 Port，但示例授权由调用方直接配置动作集合，无法表达项目停用、成员撤销、权限有效期和跨进程并发更新。

## 决策

1. 项目目录与项目成员关系使用独立 Port；
2. 平台提供固定基础角色及其治理动作映射；
3. 授权必须依次验证项目状态、成员状态、有效期和角色动作；
4. 任一数据缺失或不合法都返回拒绝；
5. 成员修改使用 revision CAS，REVOKED 为终态；
6. 项目 ARCHIVED 为终态；
7. PostgreSQL 历史表必须 append-only；
8. PostgreSQL 授权在一个只读事务中读取项目和成员；
9. 身份认证继续由独立上游边界负责。

## 结果

优点：

- 项目隔离和成员生命周期可持久化；
- 查询与治理服务复用同一授权 Port；
- 暂停、撤销和过期立即影响授权；
- CAS 防止并发管理覆盖；
- 授权逻辑可在内存和 PostgreSQL 间复用。

代价：

- 角色暂时是平台固定集合；
- 授权读取增加项目和成员查询；
- 外部身份与组织目录仍需后续适配；
- 项目成员管理接口尚未开放。
