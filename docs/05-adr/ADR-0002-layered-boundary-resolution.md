# ADR-0002：分层边界解析

- 状态：Accepted
- 日期：2026-07-27

## 决策

使用 `GLOBAL < DOMAIN < PROJECT < ENVIRONMENT < RELEASE` 五层优先级。每条规则通过 `boundaryKey` 参与继承和覆盖，并由 `overridePolicy` 控制是否可修改。

## 原因

- 多项目需要共享公司基线，同时保持业务边界独立；
- 环境参数和发布特性需要受控覆盖；
- 显式解析链便于审计和变更影响分析。

## 后果

- 同层冲突直接失败；
- 强制规则不能关闭；
- 领域包冲突必须显式处理；
- 每个最终规则保存完整来源链。
