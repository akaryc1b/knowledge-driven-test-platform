# ADR-0004：异步 Registry Port 与追加式知识版本

- 状态：Accepted
- 日期：2026-07-27

## 背景

M0 直接从 JSON 文件读取已发布规则，尚不能支撑多项目知识的草稿、审核、发布、废弃和并发编辑。若核心领域直接依赖数据库或 HTTP，将使后续适配器替换困难，并把治理规则泄漏到基础设施层。

## 决策

1. 定义异步 `KnowledgeRegistryPort`，领域调用方只依赖端口；
2. 首个适配器使用内存 Map，并通过可复用合同测试固定行为；
3. 知识对象使用逻辑 ID 与严格 SemVer 组成唯一键；
4. 已注册版本不允许删除或覆盖；
5. 仅 DRAFT 内容允许替换；
6. 状态变更只通过纯领域函数执行；
7. 每次写入使用 revision CAS；
8. 所有读取返回防御性副本；
9. 已发布内容的业务字段不可修改，变更必须创建更高版本。

## 后果

### 正面

- 内存、PostgreSQL 和未来远程 Registry 可共享相同行为；
- 发布历史和测试证据可以稳定引用精确版本；
- CAS 能在没有数据库实现前固定并发语义；
- 已发布知识不会因后台编辑被静默改变。

### 代价

- 新版本需要显式创建，不能原地修改；
- 多记录原子操作暂未提供；
- 当前内存实现不提供进程重启后的持久性；
- 身份认证与权限校验必须由后续治理服务承担。
